# Legacy AI — Solutions

Source, artwork, fonts and catalog for [Legacy AI](https://legacyai.space).

The site includes Thesis, Intake, Solutions, Board and The Deal, with the approved layered paper design and distinct category photographs. The illustrated 23-page field guide covers all 54 services with its own petrol, copper and warm-white palette.

## Publishing

The existing Vercel project `legacy-floydslabs/legacy_site` is connected to this repository. Its production branch is `main`; production deployments automatically receive the existing domains, including `legacyai.space`. Future edits belong on `preview`. Pushing that branch triggers a Vercel Preview deployment. Merge reviewed changes to `main` when they are ready for the live domain.

The preview deploy hook is managed in Vercel → Project Settings → Git. It rebuilds the latest committed `preview` branch. A deploy hook does not copy files or push commits to GitHub. Its secret URL must stay out of this repository. The Git integration already handles branch pushes, so a second GitHub Actions deploy call is unnecessary.

## Build and local preview

With Node.js installed:

```sh
npm ci
npm run build
npm test
npm run dev
```

The preview runs at `http://localhost:4187`. Public sources are in `dist/`. Vercel's build copies only public assets into `.vercel-static/`; `/api/board` is a native Vercel Function using the existing real AI Gateway backend. `vercel.json` selects the static framework and sets the Board function duration to 120 seconds.

The deployed AI features use Vercel's project identity (OIDC); local runs use an explicit `AI_GATEWAY_API_KEY`. No credentials are stored here. Its prompt and provider contract were ported from the prior production website. See `docs/board-port.md` for provenance and limits. Tests verify routing/validation and the streaming contract without making paid model requests.

## Catalog

The downloadable field guide is `dist/catalog.pdf` (23 pages, 5.7 MB). Its portable editable source, six new illustrations, fonts, exact image prompts and build instructions are in `catalog/`. The download links carry the PDF's content hash so updated editions are identifiable. Earlier editions remain in Git history.

## Search and AI visibility

`dist/robots.txt` welcomes search and AI crawlers and keeps the API out. `/owner/` stays unindexed through its noindex tag and the `X-Robots-Tag` header rather than a crawl block, so crawlers can always read that directive. `dist/sitemap.xml`, `dist/llms.txt` and `dist/llms-full.txt` are generated by `npm run build:seo` (also part of `npm run build`) from `dist/service-catalog.json` — run it after catalog or page edits. Each public page carries its own title, description, canonical URL, social card (`dist/og-solutions.jpg`) and JSON-LD structured data; `/solutions/` embeds the full service list between the `seo:services-jsonld` markers. `test/seo.test.js` guards all of it.

## Working service tools

`/contact-health/` checks visitor-supplied CSV data entirely in the browser. It flags missing details, exact duplicate rows and shared-contact conflicts. The report opens after a real inquiry is saved; the inquiry contains the visitor’s contact details and request, never the uploaded contact list. Run its focused checks with `node --test test/contact-health.test.js`.

`/receptionist/` is a test line for The Receptionist Who Never Calls In. Visitors describe their business (hours, services and prices, notes, English and/or Spanish) and bookable hours, then play the caller by typing or by voice. Voice uses the browser's Web Speech API when it is available and falls back to typing. Every reply is a live AI Gateway turn from `/api/receptionist` (`lib/receptionist.js`), grounded only in the visitor's details. The server drops any appointment time it did not offer and holds a time only once a name and callback number have been captured. Like the Board, it requires a saved inquiry with granted reply consent, and it spends a persistent allowance (60 turns per inquiry per hour, 600 per day) before generating. Nothing is booked or sent, and test calls are not stored. The model defaults to `CONCIERGE_MODEL`; `RECEPTIONIST_MODEL` overrides it.

`/booking/` turns weekly hours, buffers, notice and an optional `.ics` export into the open times a customer would be offered, entirely in the browser. Test bookings drop out of the offered times and can be downloaded as `.ics`. Repeating events block only their first date, and the page says so.

`/missed-call/` drafts missed-call text-backs (during hours, after hours, a follow-up nudge and optional Spanish versions). It shows live GSM-7/UCS-2 segment counts and checks for business identification, opt-out wording, public link shorteners, capital-letter shouting and curly quotes that cost extra segments. Nothing is sent.

Both local tools offer an optional inquiry but work without one. `/booking/core.js`, `/missed-call/core.js` and `/receptionist/core.js` are pure modules covered by `test/booking.test.js`, `test/missed-call.test.js` and `test/receptionist.test.js`.

The “Compare & plan” panel compares up to three actual catalog services and helps visitors send a project inquiry. A brief download appears only after the server confirms the saved inquiry. Board questions also require a real saved inquiry before generation. Contact details carry across tools in the same tab; each new request records its own reply and optional marketing choices. The brief also explains actual service selections, opened service links and separately labeled AI recommendations. Visitors can remove suggested interests before sending. These signals stay in the tab until included in the reviewed inquiry. There are no canned AI responses or pretend receipts.

Public forms also save visitor-stated identifying details, including unfinished forms, with a visible notice and source evidence. Free-text identification distinguishes the visitor’s details from third-party references. Anonymous activity alone does not create a contact. Draft checkbox signals are separate from submitted consent receipts.

## Site assistant (ElevenLabs)

The main public pages embed the ElevenLabs agent "Legacy AI Site Assistant (legacyai.space)" (`agent_8301m3qayesnf9r8mbtbrazgpnst`) in the bottom-left corner, for voice or text. It uses the licensed Burt Reynolds™ Iconic voice without claiming to be him. Its knowledge base is `dist/site-knowledge.txt`, generated by `build-knowledge.mjs` from every public page and re-synced daily by ElevenLabs from this repository's `preview` branch. The widget only runs on legacyai.space and the preview domain, and the page works if it fails to load.

When a visitor or caller wants Douglas, or asks something the site does not answer, the agent calls `/api/assistant/notify` with the `ASSISTANT_TOOL_SECRET` header. `lib/assistant.js` logs the event, detects a second similar unanswered question on the same day (one trending alert per question per day), and emails the owner through `OWNER_NOTIFY_WEBHOOK_URL`. The recipient is fixed in code; nothing can be sent to anyone else. If the database is down it still emails. If the endpoint is unreachable, the agent falls back to a second ElevenLabs tool that posts to the same Zapier hook with the recipient locked.

`/api/owner/digest` sends a noon and 6 pm (Indianapolis) update listing escalations, new inquiries, visitors who shared details and, when `ELEVENLABS_API_KEY` is set, every assistant conversation. Vercel Cron calls it four times a day with `CRON_SECRET` to cover daylight and standard time, and the handler sends once per slot. Crons run on production deployments only. Apply `migrations/0003_assistant_events.sql`; the handler also creates the table on first use. Tests: `node --test test/assistant.test.js`.

## Private CRM and assistant

`/owner/` uses managed Neon Google sign-in. Every owner API independently verifies the signed session and permits only the explicitly named, verified owner email. Visitor contacts, source evidence, inquiry submissions, separate consent events, and unsent reply drafts use PostgreSQL. The PA reads actual records; public chat has only the approved service catalog. Contact export is CSV: up to 10,000 recent captured visitor records and 10,000 submitted inquiries, with service interests, source context and authoritative consent separate from draft signals. Identifiers are visitor-stated; names/IP addresses never automatically merge people.

Preview storage is the dedicated `legacy-ai-site-crm` database. Apply migrations in filename order through the authenticated database console. Database credentials are Vercel Preview environment variables; none are committed. The Auth URL is public configuration. The runtime uses the existing Vercel AI Gateway and the configured/default model with bounded requests and no automatic retries. `node --test test/concierge-backend.test.js` verifies real SQL transactions and cryptographically signed owner-token boundaries. Live provider login and model calls are verified separately from these local checks. Production needs its own storage/auth configuration before this preview branch is merged.
